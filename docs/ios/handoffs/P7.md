## Concrete corrections

| Finding / trigger | Resulting source behavior | Entry points |
|---|---|---|
| Initial JobQueue restoration needs to rewrite interrupted records, but disk save fails; Retry storage could save empty pre-start memory | Track successful start separately from queue allocation; retry initial start/load, use persistence retry only after successful start | IOSTranscriptionController, IOSExportController |
| Model/job storage cannot load durable dependencies | Block model removal and project Trash/empty actions until storage recovery; preserve files rather than assume no queued jobs | IOSSpeechModels/View, IOSProjectsModel |
| Speech work runs as the app leaves the foreground; native shutdown may throw an ordinary error under cancellation | Pause/requeue through existing JobQueue; resume on return; normalize cancellation after unload/lease release | IOSProjectsView, IOSTranscriptionController, IOSLocalTranscriber, IOSTranscriptionView |
| Search/filter/sort or thumbnail work completes after a newer request | One guarded library publication checks generation and captured criteria; storage publishes all three results for its latest generation | IOSProjectsModel |
| Photos preparation overlaps Create/another source pick; active import accepts further picks which later get cleared | Observable Photos preparation state, busy guards in model and disabled conflicting UI; stale/dismissed photo results are removed and cancellation exits the loop | IOSProjectsModel, IOSImportView |
| Another scene/storage action can list/discard a live staged import while the importer awaits metadata | Repository owns an active staging set, filters it out of recovery/cleanup listings and rejects direct cleanup; release after commit or discard | IOSProjectRepository |
| Process death leaves Photos/URL ingress-only copies | Clean those two temporary ingress directories at app-model initialization; partial Photos copy errors/cancellation remove their own copy | IOSProjectsModel / IOSPickedMovie |
| Trash primary document is corrupt but its prior-valid document is readable | Projects and Trash share the recovery read; future schemas still fail closed | IOSProjectRepository |
| Valid 256-character project title cannot duplicate; clock rollback invalidates next save date | Truncate only the copy's title before adding suffix; keep updatedAt nondecreasing | IOSProjectRepository |
| Nonfinite source dimensions/transform reach Int conversion; malformed count metadata can overflow addition | Validate numeric dimensions/transform before conversion; use disjunction instead of track-count addition | IOSMediaInspector, IOSProjectDocument |
| Apply unchanged timing fields rounded to milliseconds, possibly collapsing short intervals or creating false manual timing | Reuse exact rational endpoints for unchanged display strings; identical word/cue timing is a no-op | IOSCaptionSnapshot / IOSEditorTime, IOSCaptionEdits, IOSProjectDetailView |
| 80 emoji/complex characters exceed filename byte limit during final export publication | Keep the old 80-character rule and whole graphemes, additionally cap basename at 251 UTF-8 bytes (+4 for extension); old valid output names stay the same | IOSExportRequest |
| Model selection/offline state and canvas fields need explicit accessibility semantics; import copy refers to nonexistent later stages | Selected traits/availability hints, numeric field labels, Photos loading and current Media/export wording | IOSSpeechModelsView, IOSImportView |

The JobQueue startup issue was traced against the pinned 1.0.0 package source: start() may fail its restored-record rewrite before publishing records/hasStarted; generic save-failure retry persists current memory. This PR fixes the two app callers, without modifying the package or unrelated apps.

## User-run validation sequence

1. **Packaging/compile:** independently generate/build the iOS target with default project.yml and no weights. Confirm Mac target identity/resources remain unchanged. Development Debug and Release both permit explicit downloads. If choosing a bundled production build, use project-ios-bundled.yml with the exact required Small file; missing file must block generation, cached Tiny/Base must not be used and no download action is available. See MODELS.md for paths/hashes/policy. No production packaging decision is made automatically here.
2. **Baseline workflow:** Photos video, Files audio/video and iCloud provider → local project → selected model/language transcription → edit a phrase/timing, split/merge and undo/redo → all four styles/effects → trim/crop/volume → MP4 at each resolution and SRT → Photos/Files/native share. Reopen/duplicate/Trash/restore; verify original/raw identities remain intact and duplicate deletion does not break its source.
3. **Queue recovery:** arrange a saved processing/pausing record, then an initial restore-rewrite failure (disk full/unwritable store). Retry storage after fixing disk access; saved jobs must survive instead of becoming an empty queue. Also check normal load failure and later save failure for each queue. No automatic queue reset. A genuinely corrupt top-level queue file remains preserved with a blocking error; backup/support recovery is manual, not silently erased.
4. **Interruptions:** background/foreground or kill/relaunch during model load, inference, result publication, MP4 render/finalization and export queue acknowledgment. Speech/export restart from the frozen operation, not a media/window checkpoint. Cancellation during native synchronous loading may take time; actual result publication can win a late cancellation. Change model preference while a job is pending/running: it must keep its captured variant. Explicit retry before publication may use the newly chosen variant.
5. **Race/ingress:** rapidly type search and change filter/sort while thumbnails complete; final visible library must match current criteria. During Photos preparation/import, conflicting source picks/removal/Create must be unavailable. Dismiss during Photos preparation, reopen and retry without stale selections. Inspect Storage from another scene during an import: live staging is absent from cleanup; kill/relaunch makes abandoned staging recoverable/discardable. Committed projects survive temp cleanup; existing partial-commit recovery remains intact.
6. **Exactness/names:** Apply unchanged fractional/sub-millisecond cue/word fields and verify no new manual timing/revision/undo operation; change one endpoint and preserve the untouched endpoint. Duplicate a maximum-length title; export long Vietnamese/emoji/ZWJ titles, reserved characters and a title of “partial”. Roll the wall clock back before saving. Corrupt a Trash primary document with a valid previous document and restore it; a future schema must not fall back destructively.
7. **Media/render:** rotated/mirrored/HDR/VFR sources, offset audio/video tracks, audio-only/silent media, start/end trims through a word, retained gaps/black-only ranges, extreme crop/aspect and gain 0/partial/1. Compare preview/export at the same output PTS; inspect AAC sync, actual dimensions/codecs/duration/color. Reset trim must reveal canonical captions. Edited SRT must match retained zero-based timing including overlaps/very short intervals; blank/oversize caption errors stay clear.
8. **Models/storage/delivery:** real Tiny/Base/Small download/hash, cancel while transferring/verifying, interruption/relaunch, corrupt/oversize/truncated/non-200/timeout/low disk, explicit retry and remove. Pending/running jobs block model removal. Clearing thumbnails/Trash preserves installed models and captions. Close/open export UI, deny Photos add permission, cancel Files/share, and ensure delivery completion releases its lease without allowing in-use artifact deletion. Export remains reachable after its project is trashed.
9. **Accessibility/device:** iPhone SE2 keyboard and large Dynamic Type, VoiceOver reading/selection/sliders/errors, light/dark/Reduce Motion surrounding UI, long captions/library and repeated navigation/playback/seek. Measure native memory/latency, model suitability, thermal behavior and export performance on supported devices yourself.

## Remaining choices and limits

- No storage reset UI or new recovery subsystem was invented. Future schemas/unrecoverable queue documents stay preserved with errors. Disk/permission/provider failures can still block operations until resolved. Backup/repair and final release validation belong to the user's operational decision.
