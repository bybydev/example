## Contracts implemented / deferred

- `Inkribe/Domain/MediaTime.swift`: rational nonnegative `CMTime` stamp, validated decode, strictly positive half-open ranges, identity speed clip map between source and composition time and consistency checks on decoded clip mapping. No milliseconds-based stored frame approximations.
- `Inkribe/Domain/ProjectContract.swift`: UUID-based `ProjectRevision`, `ProjectEditToken`, protocol for expected-revision transaction application. It does not persist or mutate project data. `initialVersion=1` records schema intent, **not** a shipped disk schema.
- P1 must define authoritative project document, owned originals/paths, one repository, staged asset copy+atomic commit, versioned decoding/migration/recovery, rollback from failed migrations, unsupported-version errors and durable storage fixtures before saving content. P3 must supply command operations, serialized revisions and undo/redo; UI state must not bump revision.
- `Inkribe/Rendering/CaptionScene.swift`: immutable example snapshot with project revision, UUID words/cue interval, max 16 words and `1920*1080` pixel budget; deterministic upcoming/active/spoken word states based solely on media timestamp; fixed 3-word fixture. No word alignment inferred or persistence created.
- `Inkribe/Rendering/ClipFrameCompositor.swift`: source-only render of an already-decoded/oriented clip frame. Centre-crop aspect fill; CoreText glyph runs rendered to a bounded bitmap; CoreImage overlay; BGRA destination CVPixelBuffer with caller-owned CIContext. Both future preview/export adapters must feed the same snapshot and CMTime. No replay clock, AVAssetReader, AVPlayer, AVAssetWriter, audio, final export, recording or UIKit/SwiftUI feature controls.
- P4 owns full style/typographic/animation semantics, font availability, cache keys; P5 owns source frame scheduling, output container/codecs, audio, color/HDR and actual preview/export parity; P6 owns speed/ramp/reverse/repeats/gaps/transitions. All are still pending.

## Renderer decision and alternatives

**Chosen for feasibility implementation:** Pure scene evaluation on rational project time, CoreText/CoreGraphics caption drawing and Core Image compositing over an input CIImage/CVPixelBuffer. `CIContext` and pixel buffers are supplied/reused by caller; memory in this function is bounded to one 1080p-equivalent bitmap and at most 16 words.

**Compared by source design only:** SwiftUI animation clocks (not reliably sampleable on an offline export timeline); AVVideoCompositionCoreAnimationTool/CALayer time-based composition (would require controlling media vs transaction animation clocks and parity across preview/export); custom Metal text shader/compositor (expensive font/shaping integration in P0); chosen CoreText/Core Image (shared deterministic evaluation with future writer and preview, no per-feature shader yet). **No path was built or benchmarked.**

**Unresolved/risks:** CoreText font fallback across devices, Unicode bidi/CJK/emoji shaping and line breaking, text premultiplication/color spaces, HDR/linear-light blending, coordinate orientation, exact decoded frame time under VFR, rotated media, true 4K memory/performance, output hardware encoder support, composition of more than one clip, cancellation/progress, export/playback glitches and simulator/device capabilities. Text is currently a one-line word row with a simple highlight and fixed font; no full caption styling or export feature exists.
