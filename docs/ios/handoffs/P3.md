## Integrated behavior

- Text: edit existing timed units, including phrase replacement. Preserve native word IDs/source anchors; no automatic retokenization or invented sub-word timing. Fields preserve existing whitespace separators (including no separator for CJK). Clearing hides the text; its identity/time remains and undo restores it. A corrected phrase is one timed unit until manually corrected; this is not forced alignment.
- Timing: explicit numeric project start/end seconds. Manual word time must stay inside its clip; extending beyond a cue expands that cue. Cue timing manually scales contained word intervals, preserving their relative positions. Zero/reversed/out-of-clip/collapsed intervals fail atomically. Original token/source intervals remain unchanged; optional adjustedSourceInterval records the correction.
- Split/merge: split before selected word (not first); left cue retains ID and right gets a new ID. Merge the next list cue only in the same clip, retaining the first cue ID and every word ID. Genuine overlapping native word intervals can produce overlapping split cues; no fabricated boundary removes that overlap. Preview chooses latest active cue start with deterministic UUID ties.
- Undo/redo: up to 50 commands in this open session; consecutive typing in one field coalesces, selection/focus/action changes end that group. New edits after undo clear redo. Atomic patches retain only changed words/cues plus grouping order and selection. Estimated retained payload is capped at 8 MiB by dropping oldest entries; one oversized command stays undoable. History is not persisted; edited content is.
- Preview: one stable AVPlayer with a media composition; compact footage above transport/overview/scrubber, correction/list below, smaller preview while a field has focus. Cue/word selection pauses and seeks. Playback highlights and follows active cue without replacing editing selection or taking focus. No observer-driven seek loop. Plain text overlay only; styling/motion/export remain P4/P5.

## Ownership and persistence

EditorSession owns working document, committed revision, edit/save sequence, history, selection and clock. The old P1 detail view/title-save implementation was replaced by this owner; root projects/import/storage remain. All title/caption mutations use one 600 ms debounced save drain. Captured writes commit atomically against the last returned revision; acknowledgements copy only metadata into the latest draft. New typing/undo during a write is drained afterward, never replaced by its older result. Playback/selection/focus do not save.

Failures retain draft/history and show retry plus explicit discard/reload. Normal Back, duplicate and Trash wait for saves and remain blocked on unsaved failure. No automatic stale-revision rebase. Dirty external-result refresh does not overwrite edits; same-revision background refresh does not clear undo. Explicit reload clears history. App suspension/process death before a pending debounce finishes can still leave the last saved version; atomic writes protect that version. No runtime recovery claims.

Schema current=3. v1/v2 still decode; no eager rewrite. First mutation writes v3 with prior-valid backup; older schema clients reject it. v3 adds optional adjustedSourceInterval and allows hidden/blank word text. Effective source time maps to edited project time; original native word source/timing provenance/clip/window IDs are repository-protected alongside raw/model/job fields. Duplicates retain manual timing/text and remap identities. No original media changes.
