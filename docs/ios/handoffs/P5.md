## Entry points and ownership

- IOSProjectsModel owns one IOSExportController shared by editor/Projects sheets. The editor toolbar opens IOSExportView(session: session); the Projects current-export shortcut uses session: nil, so saved delivery/discard remains reachable after all source projects are deleted.
- The export sheet pauses editing playback, ends edit groups, calls await session.savedDocument(), then exports.enqueue(document:profile:). Cancel preparation cancels that task, with cancellation checks before staging/adoption; a native fallback copy may delay observation until it returns. Unsaved/stale data cannot be silently exported as current.
- Repository prepareExport checks the canonical encoded saved document and revision. Date comparison uses its ISO-8601 disk precision rather than fractional returned Date values. It stages a version-1 manifest and hard-links referenced immutable media (copy fallback) while serialized against project Trash/purge operations. No project schema bump or original/raw-caption rewrite.
- Small IOSExportJob payload: project ID and profile; job ID identifies the staged manifest. One independent JobQueue file under Application Support/InkribeIOSProcessing/export-jobs.json, maxRecords 1. No changes to speech jobs or the Mac environment. New exports explicitly replace the prior terminal request; this is not batch rendering/history.
- Working files are under Application Support/InkribeIOSProjects/Exports/UUID: request.json, Media/UUID.ext, partial.mp4 or partial.srt, and Result/sanitized-title.ext. Result lives apart from temporary names, including a project named partial. Exports are excluded from backup. Canonical project schema remains v4.

## Media and renderer

IOSPreviewComposition.mediaGraph(document:urls:size:) returns immutable AVComposition/AVVideoComposition copies, video intervals, project duration and actual intersecting-audio presence. Preview and each export use their own graph. The @unchecked Sendable envelope is limited to these immutable copies; no AVPlayer/mutable track is shared with the export task.

The builder shares source/track intersections, source PTS offsets, original first audio/video tracks, preferred orientation, project-aspect placement and black gap instructions. Partial video-track intervals get explicit leading/trailing black instructions. Composition is SDR Rec.709. P6 should extend this builder rather than fork its mapping; crop/volume/trim tools are not introduced in P5.

IOSExportResolution.canvas(for:) fits an even-sized H.264 canvas into 1280×720 or 1920×1080 (transposed for portrait). Normal portrait is 720×1280/1080×1920; square is 720×720/1080×1080; custom ratios may have a smaller short edge. UI shows exact dimensions. No 4K/custom codec/quality catalog.

IOSMP4Exporter owns AVAssetReader/Writer, CIContext and IOSCaptionRenderer on its non-main execution task. Reader videoCompositionOutput produces the shared oriented/project-canvas frames. An interleaved loop reads bounded video/audio samples and emits H.264 frames at exact project n/30 timestamps, using renderer.overlay(snapshot:at:canvas:) for all P4 effects and typography. Intentional audio-only intervals/gaps use black; unexpectedly missing/stale source frames fail instead of silently freezing footage. VFR source placement comes from the shared composition; output is intentionally 30 fps.

Original audio is decoded as bounded stereo 48 kHz Float32 PCM through AudioMixOutput and encoded as AAC 192 kbps with its project timestamps. Silent/no-intersecting-audio projects omit AAC rather than fabricate source audio. P6 can add the same mix to preview/export; no background music/multi-track/volume tools yet.

App-owned media references are limited to current/pending decoded video samples, one audio sample, a six-buffer output pool and one active caption layout/bitmap. Pool exhaustion waits for recycling. No whole-file PCM, frame list, movie Data or unbounded callback tasks. Native AVFoundation/GPU memory and actual throughput remain unmeasured. The writer's blocking finalization cancellation hook is dispatched off MainActor; ordinary writer/reader/render access stays on its worker.

The MP4 space estimate checks important-usage capacity when available. H.264 bitrate is five bits per output pixel per second; this is an implementation setting, not an exact final-size guarantee. A 30-second no-progress watchdog reports a stalled encoder. Native synchronous reads/copies can delay cancellation until they return; no latency guarantee.

## Finalization, interruption and delivery

The writer ends at project duration and awaits finishWriting. Inspect nonempty regular file, numeric duration within 100 ms, exact requested dimensions, H.264 and expected AAC before publication. Publication checks cancellation then performs a same-volume rename into Result. A successful committed file is reused after a crash before the queue persisted success; its dimensions/video/audio codecs/duration are inspected again. Presence of source audio was checked against actual track intersections on the initial write, not guessed from metadata counts after source pins were released.

Failure/cancel/restart removes partial files, never project media. Frozen inputs survive failure/pause/cancel for Retry saved export. Successful publication releases Media pins. The one completed artifact remains until explicit discard/replacement. Startup removes unreferenced staging folders only after successful queue loading; persistence corruption is shown, not reset silently. Queue persistence failures can block transitions; do not claim those transitions succeeded.

Projects forwards scene activity to pause/resume the export queue. Pending/interrupted jobs restart from their frozen request, not partial frames. Closing an export sheet alone does not stop foreground work. No uninterrupted iOS background execution, frame checkpoint, model download or backend added.

beginDelivery returns a token and completed URL; replacement/discard are blocked until endDelivery. Photos holds the token through add-only authorization and performChanges completion. Files uses UIDocumentPicker(forExporting:asCopy:true), share uses UIActivityViewController with URL items; no movie is loaded into memory as Data. Native callbacks/dismissal release the token. Only successful destination callbacks report saving/sharing; cancellation is not success. The iOS-only NSPhotoLibraryAddUsageDescription is the only project.yml change; library read access/App Group/share extension remain absent.

StorageUsage includes exportBytes, displayed as Current export. Logical folder sizes can count hard-linked bytes in both project and export totals; actual allocated space may be smaller. Discard current export from the Projects export sheet to release retained failed/cancelled inputs or a completed local file.

## SRT semantics

IOSSRTExporter streams one UTF-8 cue at a time, using IOSCaptionSnapshot.text(for:) and edited cue project intervals. Sort by start time then stable cue UUID, skip hidden/empty cues, remove blank internal lines to preserve SRT block boundaries, and keep Unicode/text. Round start down/end up to milliseconds; genuine sub-millisecond cues remain positive without inventing word timing. Overlapping cue timings remain overlapping. Some subtitle players handle overlap/inline markup differently from preview's latest-active-cue rule. Fonts/colors/animation are in burned MP4, not plain SRT. Empty SRT fails clearly.
