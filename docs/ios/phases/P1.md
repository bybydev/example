## Implementation sequence

1. Implement the chosen iOS project repository/store root with stable IDs, schema version and content revisions. Keep a single authoritative owner. Separate originals/documents from rebuildable thumbnails/waveforms/caches and job metadata.

2. Add Photos/Files/audio/video imports, batch-as-projects and combine-as-clips flows with clear user choices. Read metadata including orientation, duration, dimensions, frame rate and audio tracks. Copy external sources through staged app-owned files before project/job commit; cancellation removes incomplete copies.

3. Implement share-extension/media-provider/direct-URL ingress where supported, respecting scoped permissions, app-group boundaries where required and explicit remote downloads/rights. The extension hands durable intent/media to the app through a documented boundary; do not create a parallel project store.

4. Build basic Projects dashboard, thumbnails, title search/sort/filter, reliable autosave/offline reopening and storage management. Present a compact UI plan before implementation. Normal launch opens Projects; welcome/create is onboarding or empty state.

5. Preserve immutable originals and serializable non-destructive multi-clip references. Implement safe project/import duplication identity rules even when advanced user-facing duplication arrives in P12.

6. Handle missing/corrupt sources, low storage, failed metadata/decode, cancelled imports and unsupported future schema without destructive reset. Define migration fixtures/recovery plan. Connect transcript search when P2 provides content and camera entry when P9 provides capture; record pending IDs/integrations explicitly.

## Contracts and preservation

- Atomic import commit: authoritative asset plus valid document before enqueue/public success.
- Path validation, ownership-aware cleanup and project revisions; sources never disappear due to cache purge.
- New iOS documents do not migrate, share or overwrite the Mac transcript store.

Preserve existing Mac behavior/data/purchases. No implicit cloud calls, paid use, model downloads, external publishing or deployment. Do not introduce placeholder controls/results and call them complete.

## Implementation completion criteria

- Projects can be created from implemented import sources, persisted, reopened and browsed offline through actual app flow.
- Interrupted import/save paths preserve the last valid document and do not report success prematurely.
- Each mapped source/library item is integrated or explicitly reported as dependency pending/blocked; no inactive demo import sources.
- P2 receives durable source references/metadata; P3 receives repository and mutation contracts.
