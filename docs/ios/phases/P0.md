## Implementation sequence

1. Audit all current target/scheme/test-host references and inherited macOS settings. Record Mac Release/Debug bundle IDs, displayed/product name, data paths, StoreKit IDs, entitlements, signing and source memberships before editing.

2. Rename the macOS XcodeGen target/scheme to InkribeMac and update dependent target references. Preserve existing Mac IDs/name/data and behavior. Add the iOS application target/scheme Inkribe with isolated platform settings, assets, entitlements, StoreKit configuration and AppFoundation dependency. Choose distinct iOS identifiers; do not create App Store resources or reuse Mac commerce IDs accidentally.

3. Choose an iOS app source layout and minimal app composition boundary. Define where project/domain/session/render adapters will live; reuse portable packages without extracting speculative packages. Do not implement P1 import, P2 inference or P3 editor UI.

4. Specify schema/version/identity, source-to-project time, editor command/revision and render snapshot contracts using ARCHITECTURE.md. Define migration/recovery responsibilities before any persisted editor schema is introduced.

5. Implement a tightly bounded renderer feasibility spike against representative timed text/word highlights and a simple clip composition. Compare actual feasible technology paths and record the chosen preview/export approach, font/easing/time sampling and P6 extension seam. Any UI prototype requires the existing UI approval. Do not download media/models or run the spike/build/tests without authorization; distinguish prototype code/source evidence from unperformed execution.

6. Inspect runtime/package platform declarations and native artifact assumptions. Record unresolved iOS compatibility and model choices in DECISIONS/RISKS. Reconcile local Mac command references only where target isolation requires it; do not configure or repair CI.

## Contracts and preservation

- Target identity and data/purchase preservation table; separate iOS settings/StoreKit namespace.
- Domain/time/render interfaces and explicit choice record. Proposed interfaces must be implementable without making Mac Transcript a video project.
- No generated .xcodeproj edits, model downloads, provider provisioning or performance claims.

Preserve existing Mac behavior/data/purchases. No implicit cloud calls, paid use, model downloads, external publishing or deployment. Do not introduce placeholder controls/results and call them complete.

- P1 can implement its project schema/import without rediscovering ownership; P4/P5 can follow the chosen renderer contract.
