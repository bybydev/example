## Implementation sequence

1. Build production composition/encoding from immutable project snapshots using P4 layout/time/effects. Honor orientation, VFR source timestamps, rational target fps, audio offsets, fonts, alpha/color and resolution. Do not create a separate typography engine for export.

2. Implement supported MP4/MOV codecs/profiles, 720p/1080p/4K, fps/bitrate/quality/aspect choices, burned-in/video-only/embedded subtitle modes, alpha/chroma overlays and independent SRT/VTT/ASS/SSA/TXT/JSON outputs as mapped. Record specific unsupported codec/container features with evidence and substitute UX.

3. Implement specialized caption modes including audio-only visualizations, karaoke/lyrics, accessible/traditional, podcast/quote/story/demo/etc. Each mode must define actual layout/content/render behavior. Bilingual and localized output plumbing consumes P7 tracks; leave content generation/integration pending until it exists.

4. Add persistent render jobs with actual stage progress, cancel/retry, temporary output cleanup, failure recovery and export history. Respect iOS suspension; never promise uninterrupted background completion. Preview, estimate size/requirements honestly, and commit successful output atomically.

5. Use native share sheet and Save to Photos/Files with scoped permissions/errors. Preserve original projects/assets on failure.

6. Integrate AppFoundation commerce using distinct iOS products and centralized verified entitlement policy. Implement free/paid access, selected plan types/trials if approved, restoration, cross-device StoreKit entitlements, watermark/export-quality rules and subscription management. Ask for unspecified prices/limits rather than inventing them.

7. Validate policy at export initiation and a clearly defined finalization boundary, with explicit revocation/cancellation behavior. Existing project content remains readable and required assets remain resolvable when premium access changes. Integrate catalog gates with P4/P10 as they arrive.

- Export jobs capture revision/profile/asset dependencies; edits during export do not mutate output.
- Caption mode and separate subtitle files are explicit, compatible profile choices.
- One verified commerce source and app-layer policy; no shared renderer/domain hasPro branching.

Preserve existing Mac behavior/data/purchases. No implicit cloud calls, paid use, model downloads, external publishing or deployment. Do not introduce placeholder controls/results and call them complete.
