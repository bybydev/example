## Implementation sequence

1. Implement native front/rear camera capture, microphone selection where supported, resolution/frame-rate presets, preview/composition guides, countdown/timer and monitoring. Handle permission-denied/restricted, route change and capture-session interruption explicitly.

2. Implement script editing, scroll speed/position, voice-following prompter, compatible remote controls and multiple takes. Voice following must not create an unbounded competing inference/session owner.

3. Implement opt-in script generation/rewriting with preview and explicit application; preserve original scripts. Reuse approved runtime/provider architecture rather than creating a separate hidden AI pipeline.

4. Persist completed/partial recoverable recordings in P1's owned storage, close and adopt files safely, and route each selected take into the normal P2 auto-caption flow. Avoid duplicate jobs when interruption/relaunch repeats the transition.

5. Refine camera/prompter/take-selection UI before alterations. Integrate P1 camera import entry point and direct-record feature ID; no dummy camera tile while capture is unavailable.

6. Document platform restrictions on input devices/monitoring/remotes and recovering interrupted containers. The user will test actual camera/audio/device behavior.
