## Implementation sequence

1. Present and settle the actual editor layout before UI alterations: one tool hierarchy, compact video preview above caption list, timeline/list relationship, small-height and keyboard-open layout, selection behavior and accessible controls.

2. Implement one project editor/session owner for document commands, revision, selection and player synchronization. Keep playback/scroll/panel state separate from persisted content. Project switching cancels stale observers/tasks and does not let old seek results affect the new project.

3. Implement two-way transcript/word/cue/timeline editing, waveform, split/merge/move/trim/insert/delete, line breaking/segmentation limits, sync offset, reading-speed/duration checks, search/replace and bulk operations.

4. Make commands atomic and reversible with multi-level undo/redo. Text changes flag timing validity or offer explicit alignment; do not delete source media when removing captions. Preserve stable word/cue IDs where semantics permit and define identity behavior for split/merge.

5. Implement timeline zoom/snapping/frame stepping, multi-selection, gestures/context menus/numeric timing, looping/playback speed/fullscreen/before-after, inspector/panel state, haptics, style copy/paste hooks, keyboard navigation/shortcuts and adaptive iPad/external-preview paths per inventory.

6. Persist content through P1 autosave and surface failures without resetting the session. Avoid reloading/reparsing/rebuilding the transcript on opening sheets or changing panels. Wire per-word styling hooks to P4 without presenting unimplemented tools as functional.

## Contracts and preservation

- One selection/playhead/cue mapping with controlled seek/playback feedback.
- Edit commands define inverse, affected IDs, revision and dirty state; asynchronous derived changes carry expected revision.
- Editor UI does not own independent stores, raw transcription mutation or inference scheduling.

Preserve existing Mac behavior/data/purchases. No implicit cloud calls, paid use, model downloads, external publishing or deployment. Do not introduce placeholder controls/results and call them complete.

## Implementation completion criteria

- All owned caption/editor productivity features work through commands and the actual app flow; preview remains visible during correction.
- State/selection and undo behavior are internally coherent after text/timing edits; content survives through durable save contract.
- Navigation/panel changes preserve project/player identity. Timing invalidation and explicit realignment paths are visible and recoverable.
- P4/P6 have stable command/selection/inspector hooks rather than adding another editor state owner.
