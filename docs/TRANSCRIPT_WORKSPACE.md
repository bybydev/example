# Inkribe — Transcript Workspace Contract

## Purpose

Phase 5 turns durable transcription output into a local Mac document workflow. The Library and transcript editor consume the Phase 4 repository/media pipeline without changing JobQueue ownership or duplicating transcript state.

## Ownership

`JSONTranscriptRepository` remains transcript-content truth.

`JobQueue` remains processing-state truth.

The Library/editor may read queue records to protect destructive operations, but they do not schedule transcription or maintain a second processing state machine.

## Library

The Library reads durable `Transcript` documents and provides:

- newest-first default ordering
- oldest-first and title sorting
- local search across title, raw transcript text, and edited transcript text
- transcript metadata/excerpts
- rename
- delete
- Record/Import entry points
- direct navigation into the transcript editor

Search and sorting live in `InkribeCore` through `TranscriptLibraryQuery`, with UI display labels kept in the Mac layer.

### Rename

Rename fetches the latest transcript by ID before mutation, trims surrounding whitespace, rejects empty titles, updates `updatedAt`, and does not advance the transcript content revision.

### Delete

Delete follows this order:

1. fetch the latest transcript;
2. inspect JobQueue records for the same transcript ID;
3. refuse deletion while any related job is waiting, transcribing, pausing, or cancelling;
4. remove terminal JobQueue records;
5. delete transcript content;
6. remove the app-owned source media when present.

Media cleanup failure is logged without transcript/audio contents. The transcript stays deleted because its content deletion already committed.

This keeps queue metadata and content ownership separate while avoiding dangling terminal queue records for deleted documents.

## Transcript editor

The editor presents one durable `Transcript` document as two explicitly different text states:

- **Edited** — writable user/AI working text.
- **Raw** — read-only original transcription output from Whisper.

Raw text is never silently replaced by manual editing. `saveEditedText` fetches the latest transcript before mutation, changes only `editedText`, increments `revision` once per persisted edit batch, updates `updatedAt`, and saves the complete latest document. This preserves newer raw text, segments, metadata, and derived fields that may have changed independently.

The editor uses a short debounce for continuous persistence and also exposes a visible Save action whenever the current edited text differs from the last successfully persisted text. Leaving the editor performs a final best-effort save for any remaining dirty text.

## Segments and search

Whisper timestamped segments remain attached to the transcript document and are not regenerated by the editor.

The editor provides:

- transcript-local text search
- match count for the active Raw/Edited text mode
- segment filtering using the same search query
- timestamp display
- click-to-seek on segment rows
- current-segment highlighting during playback
- automatic current-segment scrolling when segment search is not active

## Playback

`TranscriptPlaybackController` is a Mac presentation service backed by `AVPlayer`.

It uses the transcript's existing app-owned source media reference, so audio recordings and imported audio/video files share the same playback path.

Playback behavior includes:

- play/pause
- ±10 second skip
- scrub/seek
- duration/current-time display
- segment seek
- current-segment highlighting
- deterministic periodic-observer cleanup when the editor disappears or a new source loads

Missing or unplayable media disables playback while leaving the transcript fully editable and searchable. Playback errors are displayed separately from transcript persistence errors.

The player bar belongs to the transcript content surface inside the Phase 1 main column. The permanent shell status bar remains shell-owned beneath it; neither surface crosses into the sidebar column.

## Relaunch behavior

Transcript edits persist in `JSONTranscriptRepository`, so reopening the app-state stack restores the same edited/raw text, revision, metadata, segments, and source-media reference. Library search operates on those reloaded durable documents rather than view-local caches.

## Privacy

Library/editor diagnostics may log transcript IDs and operational failures, but must not log transcript text, segment contents, source audio/video contents, or user search queries by default.

## Phase 6 boundary

Phase 6 local AI tools should operate on the existing editable document contract:

- use transcript text as input without changing JobQueue;
- write user-approved AI results into `editedText` or `DerivedDocument` as appropriate;
- preserve raw Whisper transcription;
- use transcript `revision` / `sourceRevision` to prevent stale derived output from masquerading as current content.

Phase 6 should not replace the Library/editor persistence or playback architecture introduced here.
